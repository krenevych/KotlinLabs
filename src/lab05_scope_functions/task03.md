# Практична робота: Семантика Scope-функцій у чистому коді

**Мета:** Навчитися свідомо обирати scope-функцію (`apply`, `also`, `with`, `run`, `let`) на основі двох критеріїв:
1. **Спосіб доступу до контекстного об'єкта** (`this` чи `it`).
2. **Результат виконання лямбди** (повернення самого об'єкта чи результату обчислень).

> 📌 **Увага:** У цій роботі **не використовуються** Nullable-типи (`?`) та безпечні виклики (`?.`). Усі структури даних є гарантовано ненульовими.

---

### Модель даних

Створіть файл `OrderProcessing.kt` та додайте опис моделей:

```kotlin
data class OrderItem(
    val name: String,
    val price: Double,
    val quantity: Int
)

class Order(val id: String) {
    var customerName: String = ""
    var deliveryAddress: String = ""
    var discountPercent: Int = 0
    val items: MutableList<OrderItem> = mutableListOf()

    fun addItem(item: OrderItem) {
        items.add(item)
    }
}
```

## Завдання для виконання

### Завдання 1. Конфігурація та аудит замовлення (`apply` + `also`)
*Мета: налаштування внутрішнього стану нового об'єкта та фіксація побічного ефекту без розриву ланцюжка.*

У функції `main()` створіть замовлення з `id = "ORD-2026-001"`:
1. За допомогою **`apply`** налаштуйте об'єкт:
    * встановіть ім'я клієнта: `"Олексій Коваленко"`;
    * встановіть адресу: `"вул. Хрещатик, 22, Київ"`;
    * встановіть знижку: `10` (тобто 10%);
    * додайте до замовлення через метод `addItem(...)` три будь-які позиції (наприклад: Клавіатура, Мишка, Килимок).
2. Одразу в цьому ж ланцюжку викличте **`also`**, щоб зафіксувати подію в логах/консолі:
    * виведіть повідомлення: `"[LOG] Замовлення ${it.id} успішно налаштовано. Кількість позицій: ${it.items.size}"`.
3. Збережіть отриманий об'єкт у змінну `val order`.

---

### Завдання 2. Розрахунок підсумкової вартості (`run`)
*Мета: виконання складного обчислення в контексті об'єкта (`this`) з поверненням скалярного результату.*

Використовуючи створене замовлення `order` та функцію **`run`**, розрахуйте фінальну суму до сплати:
1. Всередині блоку `run` (де є прямий доступ до полів через `this`):
    * підсумуйте базову вартість усіх товарів (`price * quantity`);
    * застосуйте відсоток знижки `discountPercent`;
    * поверніть фінальну вартість як результат виразу (тип `Double`).
2. Присвойте результат змінній `val finalPrice: Double`.
3. Виведіть розраховану суму в консоль.

---

### Завдання 3. Обмеження області видимості та трансформація (`let`)
*Мета: ізоляція проміжної змінної та перетворення значення одного типу на інший без використання Nullable-перевірок.*

Для банківського еквайрингу суму `finalPrice` потрібно перетворити на рядок формату платіжного шлюзу.
1. Викличте `finalPrice.let { ... }`:
    * всередині блоку переведіть суму в копійки/центи (помножте на `100` і приведіть до `Long`);
    * сформуйте рядок транзакції: `"TXN-${order.id}_AMOUNT_${it}_UAH"`;
    * поверніть цей рядок як результат виклику `let`.
2. Збережіть результат у змінну `val paymentPayload` та виведіть її в консоль.

> 💡 **Зверніть увагу:** Тут `let` використовується суто за призначенням — локалізувати проміжні обчислення та трансформувати тип `Double` -> `String`.

---

### Завдання 4. Форматування та друк товарного чека (`with`)
*Мета: виклик множини методів і властивостей одного об'єкта без багаторазового повторення його імені.*

Використовуючи функцію **`with(order) { ... }`**, надрукуйте фіскальний чек у консоль у наступному форматі:

```text
========================================
ЧЕК ЗАМОВЛЕННЯ: ORD-2026-001
Отримувач: Олексій Коваленко
Адреса доставки: вул. Хрещатик, 22, Київ
----------------------------------------
Товари:
 • Клавіатура (1 шт.) - 2500.0 грн
 • Мишка (1 шт.) - 1200.0 грн
 • Килимок (2 шт.) - 800.0 грн
----------------------------------------
Знижка клієнта: 10%
Разом до сплати: 4050.0 грн
========================================
```

> **Вимога до виконання:** Всередині блоку `with` заборонено писати `order.customerName` чи `order.items`. Усі звернення до властивостей мають бути прямими (через неявний `this`).
