# Практичне завдання: Наслідування, абстрактні класи та інтерфейси в Kotlin

**Тема:** Об'єктно-орієнтоване програмування в Kotlin: модифікатори `open` та `abstract`, поліморфізм, перевизначення методів і властивостей (`override`), виклик батьківської логіки через `super`, інтерфейси з дефолтною реалізацією, множинна реалізація контрактів та безпечне приведення типів (`is`, `as?`).

---

### Мета роботи
1. Зрозуміти різницю між абстрактним класом (стан + поведінка, зв'язок *"is-a"*) та інтерфейсом (чистий контракт поведінки, зв'язок *"can-do"*).
2. Навчитися проектувати ієрархію успадкування з безпечним перевизначенням членів класу.
3. Опанувати роботу з поліморфними колекціями та перевірку реалізації інтерфейсів у рантаймі.

---

## 1. Архітектура системи (Платіжний шлюз)

Створіть файл `PaymentSystem.kt`. Вам необхідно спроектувати модуль обробки різних типів платежів інтернет-магазину.

                             │                                 │
                             ▼                                 ▼
                   ┌──────────────────────────────────────────────┐

                   └──────────────────────┬───────────────────────┘
                                          │
         ┌────────────────────────────────┼───────────────────────────────┐
         │                                │                               │
         ▼                                ▼                               ▼

## 2. Завдання для виконання

### Завдання 1. Оголошення інтерфейсів (Контракти поведінки)

1. Опишіть інтерфейс `Refundable` (Можливість повернення коштів):
    * Метод `refund(amount: Double): Boolean` — повертає `true`, якщо повернення успішне.

2. Опишіть інтерфейс `EReceiptable` (Генерація електронного чека):
    * Властивість `val receiptEmail: String`.
    * Метод `sendReceipt()` із **реалізацією за замовчуванням** (default implementation):
      ```kotlin
      fun sendReceipt() {
          println(" [E-Receipt] Електронний чек надіслано на пошту: $receiptEmail")
      }
      ```

---

### Завдання 2. Базовий абстрактний клас `PaymentMethod`

Створіть абстрактний клас `PaymentMethod`, який описує загальні риси будь-якої транзакції:

```kotlin
abstract class PaymentMethod(
    val transactionId: String,
    val amount: Double,
    val currency: String = "UAH"
)
```

**Вимоги до класу:**
1. **Валідація в `init`**: якщо `amount <= 0.0`, викинути `IllegalArgumentException` з текстом `"Сума платежу повинна бути більшою за нуль"`.
2. **Абстрактний метод**: `abstract fun processPayment(): Boolean` — специфічна логіка списання коштів.
3. **Відкритий для перевизначення метод**:
   ```kotlin
   open fun printDetails() {
       println("Транзакція #$transactionId | Сума: $amount $currency")
   }
   ```

### Завдання 3. Реалізація конкретних класів платежів

Створіть три класи-нащадки, які по-різному комбінують наслідування та інтерфейси:

#### 1. Клас `CreditCardPayment`
* **Конструктор:** `transactionId`, `amount`, `currency` (передаються в `super`), а також власні поля:
    * `cardNumber: String` (номер картки, наприклад `"4149499912345678"`);
    * `override val receiptEmail: String`.
* **Реалізує:** `PaymentMethod`, `Refundable`, `EReceiptable`.
* **Перевизначення методів:**
    * `processPayment()`: друкує `"Списання $amount $currency з картки (закінчується на ${cardNumber.takeLast(4)})... Успішно!"` і повертає `true`.
    * `refund(amount: Double)`: друкує `"Повернення $amount $currency на картку ${cardNumber.takeLast(4)} виконано."` і повертає `true`.
    * `printDetails()`: викликає батьківську версію `super.printDetails()`, після чого додатково виводить рядок: `  └ Метод: Банківська картка (**** ${cardNumber.takeLast(4)})`.

#### 2. Клас `CryptoPayment`
* **Конструктор:** `transactionId`, `amount`, `currency`, а також:
    * `val cryptoAddress: String` (адреса гаманця);
    * `val networkFee: Double` (комісія блокчейн-мережі в валюті операції).
* **Реалізує:** `PaymentMethod`, `Refundable` *(не реалізує `EReceiptable`, оскільки криптовалютні платежі псевдонімні)*.
* **Перевизначення методів:**
    * `processPayment()`: перевіряє, що списання відбувається разом із комісією. Друкує: `"Відправка $amount $currency (+ комісія $networkFee) на гаманець ${cryptoAddress.take(6)}...${cryptoAddress.takeLast(4)}... Підтверджено!"` і повертає `true`.
    * `refund(amount: Double)`: повернення можливе тільки за вирахуванням комісії мережі. Якщо `amount > networkFee`, друкує: `"Крипто-повернення ${amount - networkFee}$currency (з урахуванням комісії мережі) надіслано."` і повертає `true`, інакше друкує помилку та повертає `false`.
    * `printDetails()`: викликає `super.printDetails()` і додає рядок: `  └ Метод: Криптовалюта (Адреса: ${cryptoAddress.take(6)}...)`.

#### 3. Клас `CashOnDeliveryPayment` (Оплата при отриманні у відділенні)
* **Конструктор:** `transactionId`, `amount`, `currency`, а також:
    * `val deliveryAddress: String`;
    * `override val receiptEmail: String`.
* **Реалізує:** `PaymentMethod`, `EReceiptable` *(не реалізує `Refundable`, оскільки онлайн-повернення готівки неможливе)*.
* **Перевизначення методів:**
    * `processPayment()`: друкує: `"Замовлення зареєстровано. Оплата $amount $currency буде здійснена кур'єру за адресою: $deliveryAddress."` і повертає `true`.
    * `printDetails()`: викликає `super.printDetails()` і додає рядок: `  └ Метод: Післяплата (Адреса: $deliveryAddress)`.
    * `sendReceipt()`: перевизначте дефолтну поведінку інтерфейсу! Виведіть: `" [SMS & E-Receipt] Фіскальний чек зареєстровано та продубльовано на $receiptEmail"`.

### Завдання 4. Поліморфізм та динамічна перевірка типів у `main()`

1. Створіть поліморфний список `val payments: List<PaymentMethod>`, що містить по одному екземпляру кожного зі створених класів:
    * Картка: `amount = 2500.0`, `cardNumber = "4149499988884321"`, пошта `"client@gmail.com"`;
    * Крипта: `amount = 10000.0`, `cryptoAddress = "0x71C...B29C"`, `networkFee = 50.0`;
    * Післяплата: `amount = 1200.0`, адреса `"м. Львів, Відділення №5"`, пошта `"receiver@lviv.ua"`.

2. **Загальна обробка платежів (Поліморфізм):**
    * Переберіть список через цикл `for (payment in payments)`.
    * Для кожного платежу викличте `payment.printDetails()` та `payment.processPayment()`.
    * Зробіть перевірку за допомогою оператора **`is`**:
        * Якщо `payment is EReceiptable` — викличте `payment.sendReceipt()` *(зверніть увагу на автоматичний Smart Cast)*.
    * Виведіть розділювач рядків (`----------------------------------------`).

3. **Спеціалізована пакетна операція (Повернення коштів):**
    * Напишіть окрему функцію:
      ```kotlin
      fun processMassRefund(items: List<PaymentMethod>, refundPercentage: Double)
      ```
    * Функція повинна відібрати зі списку **тільки ті платежі, які підтримують повернення** (реалізують інтерфейс `Refundable`).
    * Виконати повернення на вказаний відсоток (наприклад, `50%` від суми) та вивести кількість успішно повернених замовлень.
